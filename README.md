# Girl Prints

Отдельная версия магазина для **физических принтов** в графической эстетике 2000-х: чёрный, хром, ледяной голубой и кислотные акценты. Основана на потоке покупки исходного проекта `art`: серверная проверка каталога → Stripe Checkout → проверенный webhook → заказ в Supabase → письма Resend.

Только главная страница. Каталог расположен на главной; корзина, контактная форма и подтверждение оплаты открываются в модалках. На телефоне модалки открываются снизу. Нет оригиналов, украшений, комиссий или отдельных страниц товаров/корзины.

## Локальный запуск

```bash
git clone https://github.com/Mariarass/printweb.git
cd printweb
npm ci
npm run dev
```

Откройте http://localhost:3001. Все команды выполняются из корня клонированного репозитория.

```bash
npm test
npm run build
npm start
```

Никакие старые `.env`, ключи, `.vercel`, Git-настройки, реальные заказы или данные покупателей не скопированы. Все переменные новой версии имеют префикс `GP_`, чтобы исключить случайное использование старых аккаунтов.

В исходном `art/tsconfig.json` добавлено только исключение `girl-prints`: TypeScript старого магазина не должен проверять вложенное независимое приложение.

## Что сейчас работает

- Шесть графических SVG-постеров для демонстрации дизайна: хромированные крылья, губы, бабочка, типографика, глаза и звезда; два размера с демонстрационными ценами.
- Визуальный ориентир — контраст и плотная типографика Bratz. Логотип, графика и постеры созданы для Girl Prints; изображения Bratz не используются.
- Категории в открытом просмотре принта: After hours, Icons, Y2K. В базе сохранены прежние ключи категорий Dreamy, Coquette, Y2K; отображение задаётся в `src/lib/types.ts`.
- В каталоге — изображение, название и цена. Описание, выбор размера и компактная кнопка Add to bag находятся в просмотре принта. Количество, удаление и сохранение корзины в браузере.
- Каждый принт открывается по картинке или названию в крупном модальном просмотре. Стрелки, клавиши ←/→, миниатюры и горизонтальный жест перелистывают фотографии только открытого принта по кругу; размер можно выбрать и добавить в корзину прямо из просмотра. На телефоне просмотр занимает весь экран.
- Меню размеров с ценами, отметкой выбора и управлением с клавиатуры; автоматически открывается вниз или вверх по доступному месту, учитывает прокрутку и границы модального окна; SVG-иконки закрытия и перелистывания.
- Модальные формы с удержанием фокуса, Escape, блокировкой фоновой прокрутки и возвратом фокуса.
- Серверные маршруты для Stripe, проверки оплаты и Resend; шаблоны писем покупателю и владельцу.
- Создание заказа по уникальному Stripe session ID; параллельные webhook/возврат не создают второй заказ.
- Письма с независимыми флагами отправки, блокировкой параллельной доставки и ключами идемпотентности Resend.
- RLS для таблиц, ограничение повторных контактных сообщений, экранирование HTML.

**По умолчанию включён деморежим.** Он не создаёт платежи. Контактная форма не сообщает об успешной отправке, если Resend не подключён.

Покупка подразумевает воспроизводимые принты: доступность задаётся `active` у товара и размера, максимум 10 экземпляров размера за заказ. Учёт конечного тиража и резервирование остатков сюда не перенесены. Админка старого магазина также не переносилась: каталог и заказы управляются в новом Supabase, платежи — в Stripe.

## Новые аккаунты и домен

Скопируйте `.env.example` в `.env.local` **внутри этой папки**. Заполните её ключами новых аккаунтов локально или в переменных окружения хостинга. Не публикуйте файл и не вставляйте секретные ключи в чат.

### 1. Supabase

1. Создайте отдельный проект.
2. Выполните `supabase/setup.sql` в его SQL Editor.
3. Укажите `GP_SUPABASE_URL` и `GP_SUPABASE_SERVICE_ROLE_KEY`.
4. Добавьте реальные товары в `gp_products`, их размеры и цены **в центах USD** — в `gp_variants`.
5. Поставьте `active = true` и у товара, и у варианта размера.

Пример структуры, **не готовый товар для продажи**:

```sql
-- Сначала загрузите собственное изображение и замените название, описание и цену.
insert into public.gp_products (id, title, description, image, category, active)
values ('your-print', 'Your real print title', 'Your real description',
        '/prints/your-print.jpg', 'Y2K', false);
insert into public.gp_variants (id, product_id, size, price_cents, active)
values ('your-print-8x10', 'your-print', '8 × 10 in', 1800, false);
```

### Несколько фотографий одного принта

В `gp_products.image` хранится основная фотография (каталог, корзина и первый кадр галереи). В `gp_products.images` — дополнительные фотографии, массив URL в нужном порядке. Например:

```sql
update public.gp_products
set images = array[
  '/prints/your-print-detail.jpg',
  '/prints/your-print-on-wall.jpg'
]
where id = 'your-print';
```

Если таблицы уже создавались раньше, сначала выполните `supabase/migrations/20261020_product_images.sql` в новом Supabase. Для новой базы колонка уже включена в `setup.sql`. Основная фотография сохраняется; при пустом массиве просмотр показывает один кадр с неактивными стрелками. Повторяющиеся URL не дублируются в галерее.

У демонстрационных принтов по три вида: исходная графика, фрагмент крупным планом и SVG-макет на стене. Это демонстрационные иллюстрации, а не фотографии готовой продукции. Они создаются из исходных SVG командой `python3 scripts/generate-demo-gallery.py`. Замените их собственными фотографиями перед продажей.

Изображения можно хранить в `public/prints` или использовать публичные HTTPS URL своего хранилища. В `src/components/Shop.tsx` замените также три демонстрационных изображения в первом экране. Идентификаторы с префиксом `demo-` запрещены для оплаты.

Заказы сохраняются в `gp_orders` вместе с составом, размером, итогом, налогом, контактами и адресом доставки. Карточные реквизиты приложение не получает.

### 2. Stripe

1. В **новом** Stripe сначала используйте test mode / sandbox.
2. Укажите `GP_STRIPE_SECRET_KEY`.
3. Создайте webhook endpoint `https://ВАШ-ДОМЕН/api/webhooks/stripe`.
4. Подпишите endpoint на:
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
5. Сохраните signing secret этого endpoint в `GP_STRIPE_WEBHOOK_SECRET`.
6. Настройте Stripe Tax для нового аккаунта. `GP_STRIPE_AUTOMATIC_TAX=true` включает автоматический расчёт, как в исходнике. Менять его следует в соответствии с настройками вашего бизнеса.
7. В Stripe настройте название магазина, branding и доступные методы оплаты.

Товары и Price ID не нужно вручную создавать в Stripe: Checkout получает `price_data` из проверенного сервером каталога.

Для локальной проверки со Stripe CLI:

```bash
stripe listen --events checkout.session.completed,checkout.session.async_payment_succeeded \
  --forward-to localhost:3001/api/webhooks/stripe
```

Для локального теста нужен signing secret, выданный этой командой, а для production — secret реального endpoint. Не смешивайте test/live ключи.

Доставка пока повторяет исходный магазин: **бесплатно, только США, валюта USD**. Страны, стоимость и налоги задаются в `src/app/api/checkout/route.ts`; синхронно обновляйте текст в корзине и Shipping & returns.

### 3. Resend

1. Подключите новый аккаунт / API key и подтвердите свой домен в Resend с указанными сервисом DNS-записями.
2. Заполните:
   - `GP_RESEND_API_KEY` — новый секретный ключ;
   - `GP_RESEND_FROM` — например, `Girl Prints <orders@ваш-домен>`;
   - `GP_CONTACT_EMAIL` — адрес для контактной формы и ответов покупателей;
   - `GP_ORDER_NOTIFY_EMAIL` — адрес уведомлений о заказах;
   - `GP_RATE_LIMIT_SECRET` — случайная строка, например результат `openssl rand -hex 32`.
3. Отправьте тестовое сообщение через форму и проверьте письма тестового заказа.

Если Resend не принимает письмо, webhook отвечает 500 для повторной попытки Stripe. Сам уже оплаченный заказ остаётся в базе. Покупателю показывается, что оплата подтверждена и повторно платить не нужно.

Ключи идемпотентности Resend ограничены сроком хранения у провайдера (24 часа). Постоянные флаги в базе защищают завершённые отправки; при редком сбое между приёмом письма Resend и сохранением флага повтор после этого срока может дублировать письмо. Доставка email не является транзакцией с базой.

### 4. Новый домен и хостинг

Разверните репозиторий `Mariarass/printweb` отдельным Next.js проектом. Root Directory — корень репозитория (`.`).

- `GP_SITE_URL=https://ВАШ-ДОМЕН` — канонический origin для redirect, metadata и проверки формы.
- `GP_SHOP_ID=girl-prints` — постоянный идентификатор магазина в metadata Stripe.
- Используйте один канонический домен; перенаправляйте `www`/другие алиасы на него.
- Добавьте DNS-записи, выданные выбранным хостингом, и проверьте HTTPS.
- Настройте все `GP_` переменные на хостинге заново.

Перед открытием продаж замените демонстрационные изображения/цены, подтвердите сроки отправки и условия возврата в интерфейсе. Затем поставьте `GP_DEMO_MODE=false`, `GP_CHECKOUT_ENABLED=true` и заново разверните проект. Сначала проверьте покупку с тестовыми ключами. Для реальных продаж переключите **оба** Stripe secret на production.

## Как проверяется оплата

1. Браузер отправляет ID размера, количество и отображённую цену. Сервер отклоняет неправильные числа, дубликаты и демонстрационные ID.
2. Сервер читает текущую цену и доступность из Supabase. При изменении цены checkout не создаётся, покупателю предлагается обновить каталог.
3. Stripe Checkout создаётся с `price_data` сервера, фиксированным доверенным origin и ключом идемпотентности попытки.
4. `cancel_url` возвращает на главную с открытой корзиной. `success_url` сам по себе **ничего не подтверждает**.
5. Webhook проверяет подпись по **исходному телу** запроса и принадлежность сессии этому магазину. Неоплаченные completed-сессии не исполняются; отложенные оплаты обрабатываются отдельным событием.
6. Состав заказа восстанавливается из Stripe, а не из текущего каталога: изменение цены после оплаты не меняет заказ. Проверяются USD, paid, сумма товаров, налог, доставка и общий итог.
7. Заказ записывается однократно по `session_id`. Затем отправляются два письма.
8. При возврате на главную сервер дополнительно запрашивает сессию у Stripe и вызывает тот же обработчик. Это запасной путь, webhook работает даже если покупатель закрыл страницу.
9. Из корзины вычитаются оплаченные позиции из сохранённого снимка этой сессии. Неоплаченный/непроверенный возврат её не очищает.

## Что обнаружено в исходном проекте

- Каталог и цены: `src/lib/orders/validate-checkout-lines.ts`, таблица `Item`.
- Создание Stripe Checkout: `src/app/actions/checkout.ts`.
- Подпись webhook: `src/app/api/webhooks/stripe/route.ts`.
- Сохранение и повторная проверка: `src/lib/orders/fulfill-paid-order.ts`, `src/app/actions/checkout-success.ts`.
- Resend: `src/lib/order-emails.ts`.
- В старом `sendContactFormEmail` результат `resend.emails.send()` не проверяется на возвращённое поле `error`; новая версия это исправляет.
- Старый webhook обрабатывает только `checkout.session.completed`; новая версия учитывает подтверждение отложенных платежей.
- В старой версии есть смешанная корзина с оригиналами, остатки, админка, комиссии и страницы работ. В новой версии покупательский сценарий упрощён до принтов и модалок.

Официальные справочники: [Stripe Checkout fulfillment](https://docs.stripe.com/checkout/fulfillment), [проверка подписи Stripe](https://docs.stripe.com/webhooks/signature), [Resend idempotency keys](https://resend.com/docs/dashboard/emails/idempotency-keys).

## Проверка и ограничения

`npm test` проверяет серверные сценарии с подменёнными внешними сервисами; тест подписи использует настоящий SDK Stripe и локально подписанный payload. `npm run build` проверяет production-сборку и типы. В браузере проверены мобильная корзина, размеры, пересчёт суммы, сохранение после reload, удаление и контактная форма.

Живая test-mode покупка, SQL в новом Supabase, DNS и реальные письма требуют новых аккаунтов и пока не проверены. Публикация не выполнялась. Здесь подготовлен самостоятельный локальный проект, а не подключённый production-магазин.
